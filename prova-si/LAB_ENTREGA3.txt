# LABORATÓRIO DA ENTREGA 3 — WINDOWS LOCAL

**Projeto Integrador — Segurança da Informação — Unit**

## OBJETIVO E LIMITE

O laboratório utiliza somente o próprio computador Windows. A varredura é restrita a `127.0.0.1/32` (loopback) e às portas TCP 22, 8000 e 8001.

O programa rejeita qualquer outro IP. Não altere esse limite para examinar Wi-Fi, rede doméstica, rede da faculdade ou Internet.

## 1. PREPARAR O PROJETO

Abra o PowerShell na pasta `prova-si`:

```powershell

.\.venv\Scripts\Activate.ps1
py -m pip install -r requirements.txt
```

Confira se o Nmap está instalado:

```powershell
nmap --version
```

Cadastre um usuário para a demonstração, caso ainda não exista:

```powershell
py app.py
```

Escolha a opção 1 para cadastrar e 3 para sair.

## 2. INSTALAR E CONFIGURAR OPENSSH SERVER DO WINDOWS

Esta etapa é necessária para ter um serviço SSH real na porta 22.

Antes de alterar qualquer configuração, abra o PowerShell **COMO ADMINISTRADOR** e confira se a porta já está sendo usada:

```powershell
Get-Service sshd -ErrorAction SilentlyContinue

Get-NetTCPConnection -State Listen -LocalPort 22 -ErrorAction SilentlyContinue |
    Format-Table LocalAddress, LocalPort, OwningProcess
```

Se o serviço `sshd` já estiver em execução ou a porta 22 estiver ocupada, não encerre processos desconhecidos nem altere a configuração existente. Pare e peça orientação antes de prosseguir.

Se a porta estiver livre, confira o recurso OpenSSH Server:

```powershell
Get-WindowsCapability -Online |
    Where-Object Name -like 'OpenSSH.Server*'
```

Se o estado estiver `NotPresent`, instale:

```powershell
Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0
```

O arquivo de configuração fica em:

```text
C:\ProgramData\ssh\sshd_config
```

Não inicie o serviço ainda. Primeiro prepare o arquivo para garantir que ele nunca escute fora do loopback durante o laboratório.

Defina o caminho e faça backup, se o arquivo já existir:

```powershell
New-Item -ItemType Directory -Force (Join-Path $env:ProgramData 'ssh') |
    Out-Null

$config = Join-Path $env:ProgramData 'ssh\sshd_config'

if (Test-Path $config) {
    Copy-Item $config "$config.entrega3.bak" -Force
}
```

**Se o arquivo NÃO existir**, crie uma configuração mínima local antes de iniciar o serviço:

```powershell
@(
    'Port 22',
    'ListenAddress 127.0.0.1',
    'PasswordAuthentication yes',
    'PubkeyAuthentication yes',
    'PermitEmptyPasswords no',
    'MaxAuthTries 6',
    'LoginGraceTime 2m',
    'ClientAliveInterval 0',
    'LogLevel INFO',
    'Subsystem sftp sftp-server.exe'
) | Set-Content -Encoding ascii $config
```

**Se o arquivo já existia**, abra-o em um editor como Administrador e ajuste as diretivas globais, que devem ficar antes de qualquer bloco `Match`. Não duplique diretivas:

```powershell
notepad "$config"
```

Mantenha ou ajuste:

```text
Port 22
ListenAddress 127.0.0.1
PasswordAuthentication yes
PubkeyAuthentication yes
PermitEmptyPasswords no
MaxAuthTries 6
LoginGraceTime 2m
ClientAliveInterval 0
LogLevel INFO
```

Deixe `AllowUsers` ausente nesta primeira medição. Preserve as demais configurações padrão do Windows.

**IMPORTANTE:** a documentação da Microsoft informa que `PermitRootLogin` não se aplica ao OpenSSH para Windows e que `KbdInteractiveAuthentication` e `X11Forwarding` não são suportadas nessa versão. O perfil Windows da auditoria não avalia essas diretivas. Não as adicione.

Gere as chaves do servidor que ainda não existam, valide a sintaxe e só então inicie o serviço:

```powershell
& "$env:WINDIR\System32\OpenSSH\ssh-keygen.exe" -A

& "$env:WINDIR\System32\OpenSSH\sshd.exe" -t

if ($LASTEXITCODE -ne 0) {
    throw "Configuração SSH inválida."
}

Start-Service sshd
```

Confirme que a porta 22 escuta SOMENTE em `127.0.0.1`:

```powershell
Get-NetTCPConnection -State Listen -LocalPort 22 |
    Format-Table LocalAddress, LocalPort
```

Se aparecer `0.0.0.0`, `::` ou outro endereço, pare o serviço (`Stop-Service sshd`) e corrija `ListenAddress` antes de continuar. Não execute Nmap enquanto a escuta não estiver limitada a `127.0.0.1`.

No laboratório realizado, a regra de entrada `OpenSSH-Server-In-TCP` do Firewall do Windows também foi desabilitada como medida adicional. Mantenha-a desabilitada durante a atividade.

## 7. REDUZIR A SUPERFÍCIE E ENDURECER O SSH

### a) Encerrar o serviço HTTP extra

Na janela B do servidor HTTP extra, pressione `Ctrl+C` para encerrar a porta 8001.

Mantenha o servidor 8000 ativo.

### b) Preparar a autenticação por chave pública

Antes de desativar a autenticação por senha, configure e teste a autenticação por chave pública.

No PowerShell, gere um par de chaves Ed25519:

```powershell
$sshDir = Join-Path $HOME '.ssh'
$key = Join-Path $sshDir 'id_ed25519_e3'
$sshKeygen = Join-Path $env:WINDIR 'System32\OpenSSH\ssh-keygen.exe'

New-Item -ItemType Directory -Force $sshDir | Out-Null

if ((Test-Path $key) -or (Test-Path "$key.pub")) {
    throw "Já existe uma chave com esse nome. Não a sobrescreva; escolha outro nome para a chave do laboratório."
}

& $sshKeygen -t ed25519 -a 64 -f $key -C "e3-loopback"
```

A passphrase protege a chave privada. Para este laboratório temporário, pode ser deixada vazia pressionando Enter duas vezes.

**IMPORTANTE:** guarde a chave privada em segurança. Nunca a compartilhe nem a envie ao repositório. Os comandos seguintes devem utilizar a mesma conta Windows e o mesmo perfil de usuário que geraram o par de chaves.

### c) Instalar a chave pública

Se a conta Windows pertencer ao grupo Administradores, a chave pública deverá ser instalada em:

```text
%ProgramData%\ssh\administrators_authorized_keys
```

O arquivo deve possuir permissões somente para `SYSTEM` e `Administrators`.

No PowerShell **COMO ADMINISTRADOR**, usando a mesma conta Windows que gerou as chaves:

```powershell
$keyPublica = Join-Path $HOME '.ssh\id_ed25519_e3.pub'
$adminKeys = Join-Path $env:ProgramData 'ssh\administrators_authorized_keys'
$adminKeysBackup = "$adminKeys.entrega3.bak"

if (-not (Test-Path $keyPublica)) {
    throw "Chave pública não encontrada. Confira se está usando a mesma conta Windows que gerou as chaves."
}

$conteudo = (Get-Content $keyPublica -Raw).Trim()

if (Test-Path $adminKeys) {
    if (Test-Path $adminKeysBackup) {
        throw "Já existe um backup anterior. Confira-o antes de continuar."
    }

    Copy-Item $adminKeys $adminKeysBackup -Force

    if ((Get-Content $adminKeys) -notcontains $conteudo) {
        Add-Content -Path $adminKeys -Value $conteudo -Encoding ascii
    }
} else {
    Set-Content -Path $adminKeys -Value $conteudo -Encoding ascii
}

icacls.exe $adminKeys /inheritance:r

icacls.exe $adminKeys /grant "*S-1-5-32-544:F" /grant "*S-1-5-18:F"

icacls.exe $adminKeys
```

No arquivo `sshd_config`, garanta que exista uma única configuração específica para contas administradoras:

```text
Match Group administrators
    AuthorizedKeysFile __PROGRAMDATA__/ssh/administrators_authorized_keys
```

Se esse bloco já existir, ajuste-o em vez de duplicá-lo. Ele deve ficar no final do arquivo, depois das diretivas globais.

### d) Restringir os usuários e preparar o endurecimento

Abra o arquivo como Administrador:

```powershell
notepad "$env:ProgramData\ssh\sshd_config"
```

Na seção global, antes de qualquer bloco `Match`, mantenha ou ajuste as seguintes diretivas:

```text
Port 22
ListenAddress 127.0.0.1
PasswordAuthentication yes
PubkeyAuthentication yes
PermitEmptyPasswords no
MaxAuthTries 6
LoginGraceTime 2m
AllowUsers SEU_USUARIO_WINDOWS
ClientAliveInterval 0
LogLevel INFO
```

Substitua `SEU_USUARIO_WINDOWS` pelo nome de usuário real do Windows, em letras minúsculas.

No Win32-OpenSSH, `AllowUsers` aceita padrões com curingas. O caractere `?` representa exatamente um caractere. Quando o nome da conta contém espaços, ele pode representar o espaço.

Exemplo utilizado neste laboratório:

```text
AllowUsers iago?messias
```

Esse padrão corresponde à conta local `Iago Messias`. Não coloque aspas em volta do padrão na configuração.

**Atenção:** mantenha a diretiva `AllowUsers` antes de qualquer bloco `Match`. Não duplique o bloco `Match Group administrators` da etapa anterior.

### e) Testar a autenticação por chave pública

Antes de desativar a autenticação por senha, valide a sintaxe e reinicie o serviço:

```powershell
$sshd = Join-Path $env:WINDIR 'System32\OpenSSH\sshd.exe'

& $sshd -t

if ($LASTEXITCODE -ne 0) {
    throw "Configuração SSH inválida."
}

Restart-Service sshd
```

Teste a conexão exclusivamente por chave pública:

```powershell
$ssh = Join-Path $env:WINDIR 'System32\OpenSSH\ssh.exe'
$key = Join-Path $HOME '.ssh\id_ed25519_e3'

& $ssh -v -p 22 `
    -l "$env:USERNAME" `
    -i "$key" `
    -o IdentitiesOnly=yes `
    -o PreferredAuthentications=publickey `
    -o PasswordAuthentication=no `
    -o BatchMode=no `
    -o StrictHostKeyChecking=accept-new `
    127.0.0.1 "whoami"
```

A autenticação deverá apresentar sucesso, com uma mensagem semelhante a:

```text
Authenticated to 127.0.0.1 ([127.0.0.1]:22) using "publickey".
```

Não desative a autenticação por senha enquanto o teste por chave pública não for bem-sucedido.

### f) Aplicar as medidas finais de endurecimento

Após confirmar a autenticação por chave, abra novamente o `sshd_config` e altere as seguintes diretivas globais:

```text
PasswordAuthentication no
PubkeyAuthentication yes
PermitEmptyPasswords no
MaxAuthTries 3
LoginGraceTime 30
ClientAliveInterval 300
LogLevel VERBOSE
```

Mantenha `Port 22` e `ListenAddress 127.0.0.1`.

**Mantenha também a mesma diretiva `AllowUsers` configurada na etapa 7(d).** No computador utilizado neste laboratório, ela é:

```text
AllowUsers iago?messias
```

Preserve o bloco `Match Group administrators` configurado anteriormente, no final do arquivo.

Valide a sintaxe e reinicie:

```powershell
$sshd = Join-Path $env:WINDIR 'System32\OpenSSH\sshd.exe'

& $sshd -t

if ($LASTEXITCODE -ne 0) {
    throw "Configuração SSH inválida."
}

Restart-Service sshd
```

Repita o teste de autenticação por chave pública e registre a saída:

```powershell
$ssh = Join-Path $env:WINDIR 'System32\OpenSSH\ssh.exe'
$key = Join-Path $HOME '.ssh\id_ed25519_e3'

& $ssh -v -p 22 `
    -l "$env:USERNAME" `
    -i "$key" `
    -o IdentitiesOnly=yes `
    -o PreferredAuthentications=publickey `
    -o PasswordAuthentication=no `
    -o BatchMode=no `
    -o StrictHostKeyChecking=accept-new `
    127.0.0.1 "whoami" 2>&1 |
    Tee-Object .\evidencias\ssh_autenticacao_chave.txt

if ($LASTEXITCODE -ne 0) {
    throw "A autenticação SSH por chave pública falhou."
}
```

A conexão deve continuar funcionando mesmo com `PasswordAuthentication no`. A evidência deve registrar a autenticação com chave pública.

### g) Confirmar a escuta e registrar a evidência

Confirme que a porta 22 continua escutando exclusivamente em `127.0.0.1` e salve o resultado:

```powershell
Get-NetTCPConnection -State Listen -LocalPort 22 |
    Select-Object LocalAddress, LocalPort |
    Format-Table -AutoSize |
    Out-File -Encoding utf8 .\evidencias\ssh_listen_depois.txt
```

A configuração deve continuar restrita ao loopback.

**Resultado esperado:** 8001/tcp deixa de aparecer; 22/tcp e 8000/tcp permanecem. A auditoria SSH deve indicar melhora em `PasswordAuthentication`, `MaxAuthTries`, `LoginGraceTime`, `AllowUsers`, `ClientAliveInterval` e `ListenAddress`.

## 11. RESTAURAR O OPENSSH APÓS A ATIVIDADE

Depois de gerar todas as evidências, restaure a configuração original e encerre o serviço.

Primeiro, pare o serviço:

```powershell
Stop-Service sshd -ErrorAction SilentlyContinue
```

Restaure a configuração do SSH:

```powershell
$config = Join-Path $env:ProgramData 'ssh\sshd_config'
$configBackup = "$config.entrega3.bak"

if (Test-Path $configBackup) {
    Copy-Item $configBackup $config -Force
    Remove-Item $configBackup -Force
} else {
    Remove-Item $config -Force -ErrorAction SilentlyContinue
}
```

Se havia um arquivo de configuração antes da atividade, o backup deve ser restaurado. Se o arquivo não existia antes, remova a configuração mínima criada para o laboratório.

Restaure também o arquivo de chaves autorizadas dos administradores:

```powershell
$adminKeys = Join-Path $env:ProgramData 'ssh\administrators_authorized_keys'
$adminKeysBackup = "$adminKeys.entrega3.bak"

if (Test-Path $adminKeysBackup) {
    Copy-Item $adminKeysBackup $adminKeys -Force

    icacls.exe $adminKeys /inheritance:r
    icacls.exe $adminKeys /grant "*S-1-5-32-544:F" /grant "*S-1-5-18:F"

    Remove-Item $adminKeysBackup -Force
} else {
    Remove-Item $adminKeys -Force -ErrorAction SilentlyContinue
}
```

Como o backup foi criado antes de adicionar a chave do laboratório, a restauração recupera o conteúdo anterior. Se o arquivo não existia, remove o arquivo criado para a atividade.

Remova o par de chaves temporário do perfil do usuário. Execute com a mesma conta Windows que gerou as chaves:

```powershell
$key = Join-Path $HOME '.ssh\id_ed25519_e3'

Remove-Item $key, "$key.pub" -Force -ErrorAction SilentlyContinue
```

Se o OpenSSH Server foi instalado exclusivamente para esta atividade, remova-o depois de parar o serviço e restaurar os arquivos:

```powershell
Remove-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0
```

Não remova backups antes de conferir que a configuração original e o conteúdo anterior do arquivo de chaves autorizadas foram restaurados.

No laboratório realizado, o OpenSSH Server não estava instalado antes da atividade e o arquivo `sshd_config` não existia. Portanto, não havia configuração original a restaurar. O serviço deve ficar parado ao final, como estava antes do laboratório.

## OBSERVAÇÕES

- Nmap mostra o que está acessível no loopback; `Get-NetTCPConnection` mostra os sockets locais em escuta.
- Porta aberta não prova, por si só, que um serviço seja vulnerável.
- O projeto restringe o Nmap a `127.0.0.1/32` e às portas presentes no JSON.
- O laboratório serve para fins didáticos e não é ferramenta de monitoramento ou auditoria profissional.
- A autenticação por chave pública foi testada antes e depois de desabilitar a autenticação por senha.
- A chave privada do laboratório não deve ser enviada ao GitHub nem compartilhada.
- A regra de entrada `OpenSSH-Server-In-TCP` foi mantida desabilitada durante o laboratório como medida adicional de proteção.
